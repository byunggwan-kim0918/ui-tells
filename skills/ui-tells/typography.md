# 타이포그래피 — 선정과 운용

§5 DNA의 타이포 항목과 §8 제작 1단계(토큰)에서 이 파일을 연다.
**§2(한글 운용)는 한국어 제품에서만 적용한다** — `.design/audit.conf`의 `DIALECTS`에 `locale.ko`가 있으면 필수,
없으면 건너뛴다. CJK가 아닌 제품에서 §2를 적용하면 자간·행간이 과하게 좁아진다.

## 1. 서체 선정
- **기존 프로젝트**: 브랜드 자산의 서체를 유지한다. 바꾸는 건 브랜드 아이덴티티 교체라 사용자 결정(SKILL §9).
- **신규 프로젝트**: 브리프의 (ii) 대상·(v) 감정 목표로 고른다. 이유를 한 문장으로 쓴다. "예뻐서"는 이유가 아니다.
  - 한글 산세리프 후보: Pretendard(중립·범용) / Wanted Sans(친근·소비자) / SUIT(기하·테크) / Spoqa Han Sans Neo(제품 UI 밀도).
  - **기본값 tell**: Noto Sans KR · 나눔고딕 · 맑은 고딕. 이유 없이 쓰면 템플릿으로 읽힌다(ai-tells §2).
  - Latin 병기: 한글 서체의 Latin 글리프가 약하면 페어링한다(예: Pretendard + Inter Tight). x-height와 굵기를 맞춘다.
  - 세리프: taste-skill §4.1 SERIF DISCIPLINE을 따른다. 한글 세리프(본명조·Noto Serif KR)는 에디토리얼·헤리티지 브리프에만.

## 2. 한글 운용 — Latin과 다르다
- `letter-spacing`: 제목 -0.02~-0.04em, 본문 -0.01~0. **양수 금지** — 한글은 벌어지면 느슨해 보인다.
- `line-height`: 본문 1.6~1.75, 제목 1.2~1.35. Latin 기본(1.5)보다 넉넉히 — 한글은 글자 상하 여백이 작다.
- `word-break: keep-all` — 어절 단위 줄바꿈. `break-all`은 단어를 찢는다.
- 한글+숫자 혼용(금액·날짜·시간·카운트)은 `tabular-nums`.
- 굵기는 서체가 실제 제공하는 것만, 한 제품에 3단계 이내(예: 500/700/800). 가짜 볼드 금지.

## 3. 타입 스케일
- 위계는 크기 하나로 만들지 않는다 — **크기·굵기·색(foreground/text-2/muted) 세 축**을 함께 쓴다.
- 제목/본문 대비 2배 이상(예: 52/17). 36/16은 소심하다(ai-tells §2).
- 스케일은 토큰으로 5~7단계만 정의하고, 화면마다 새 크기를 만들지 않는다.
- 본문 `max-width`: Latin 60~70ch. 한글은 글자 폭이 커서 34~40자(≈600~680px).

## 4. 로딩
- 서브셋 필수(한글 2,350자 또는 dynamic subset). 전체 한글 세트는 수 MB다.
- `font-display: swap` + 시스템 폴백 스택(`Apple SD Gothic Neo`, `Malgun Gothic`). 폴백과 폭 차이가 크면 FOUT 때 레이아웃이 뛴다.
- `next/font` 또는 self-host. 프로덕션 CDN `<link>`는 taste-skill §3.A가 금지 — 기존 프로젝트가 CDN이면 보고한다.

## 5. 검사
- 렌더 후 `document.fonts`로 실제 로드를 확인한다. 폴백으로 렌더된 화면을 "확인됨"이라 하지 않는다.
- 한글·숫자·Latin이 한 줄에 섞인 곳(날짜·금액 표기)을 스크린샷으로 본다. baseline이 튀면 페어링 실패다.
